# バグ報告フォームの受信設定（Google Apps Script）

紹介サイトのバグ報告フォームは、Google Apps Script の Web アプリに POST して
**自分（スクリプトの所有者）宛にメールを送る**構成になっている。
ユーザーはページから離れずに送信できる。

## セットアップ

1. https://script.google.com/ を開き「新しいプロジェクト」を作成する
2. プロジェクト名を `りまっぷ バグ報告` などにする
3. エディタの `コード.gs` の中身を全部消して、このディレクトリの
   [`Code.gs`](./Code.gs) の内容をそのまま貼り付けて保存する
4. 右上の「デプロイ」→「新しいデプロイ」を選ぶ
5. 種類の選択（歯車アイコン）で **ウェブアプリ** を選ぶ
6. 設定を以下にする
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
7. 「デプロイ」を押す。初回はアクセス承認を求められるので許可する
   （「このアプリは確認されていません」と出たら「詳細」→「安全でないページに移動」）
8. 表示された **ウェブアプリの URL**（`https://script.google.com/macros/s/.../exec`）をコピーする
9. `website/app.js` 冒頭の `ENDPOINT` にその URL を貼り付ける

```js
var ENDPOINT = 'https://script.google.com/macros/s/XXXXXXXX/exec';
```

10. コミットして push する（GitHub Actions が自動で再デプロイする）

## 補足

- `ENDPOINT` が空のあいだは、送信ボタンは従来どおり `mailto:` にフォールバックする
- スクリプトを書き換えたときは「デプロイ」→「デプロイを管理」→ 鉛筆アイコン →
  バージョンを「新バージョン」にして更新する。**URL は変わらない**
- 送信できる上限は Gmail アカウントで 1 日 100 通（Apps Script の割り当て）
- `website/app.js` 側でも 1〜1000 文字のチェックをしているが、
  直接 POST された場合に備えて `Code.gs` でも同じ検証をしている
- ボット対策として、人間には見えない `website` フィールド（ハニーポット）を置いている。
  ここが埋まっている POST はメールを送らずに握りつぶす
- `ENDPOINT` を設定したあとは `website/app.js` の `MAIL_TO` と `sendByMailto()` は
  使われなくなる。公開 JS からメールアドレスを消したければ、あわせて削除してよい
